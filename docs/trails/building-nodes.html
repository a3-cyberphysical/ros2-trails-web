Building nodes and packages

Create a workspace, package communicating nodes, and define a message type.

5 lessons · 3 learning stages · Learn entirely on this site

ImportantBefore you start

Run the local Jazzy environment check. It verifies the installation, shell, build tools, dependency tool, and network assumptions used below.

What you will make

You will create one workspace, add packages to it, run two nodes that exchange messages, and define a message type for your own domain.

ros2_trails_ws/                 workspace: the build boundary
└── src/
    ├── trail_hello/            package: code + dependency metadata
    ├── trail_py_pubsub/        package containing Python nodes
    ├── trail_cpp_pub/          package containing C++ nodes
    └── trail_interfaces/       package containing message definitions

A package is the smallest ROS 2 project unit. A build installs executable artifacts; ros2 run locates one and starts a process. That process can create one or more nodes, which are the participants visible in the ROS graph. Nodes exchange typed data over topics. colcon builds the workspace; ament_python and ament_cmake describe how Python and C++ packages are built and installed.

Route through the three stages

  1. Workspace and package: complete lessons 1 and 2.
  2. Choose one ROS programming library: use rclpy for Python or rclcpp for C++. Complete both only if you want a language comparison.
  3. Domain interface: complete the custom-interface lesson and connect Waypoint to the language branch you chose.

Checkpoint before stage 3: ros2 topic info must show one publisher and one subscriber in your chosen language, and ros2 topic echo --once must capture a sample.

Capstone: prove the complete system

Start from clean terminals and demonstrate all three stages. Use notes and copy commands freely; the goal is to select, adapt, and explain them:

Mark the trail complete only when every box has observable evidence. Mark a stage needs review when you cannot yet explain why a command is needed or predict its key output.

Complete the stages in order; choose one lesson in stage 2. Each lesson contains a local activity and knowledge check.

What you will build up along the way

1. Overview

A ROS 2 workspace is a build boundary containing packages. A package is the unit of organization and dependency declaration; nodes are runtime participants implemented inside packages. colcon builds the workspace, while ament_cmake and ament_python provide the common C++ and Python package conventions.

Key ideas

  • A ROS 2 workspace is a build boundary containing packages. 2. Core design choices

Prefer one clear responsibility per node.

Key ideas

  • Prefer one clear responsibility per node.
  • Use topics for ongoing data, services for quick request/response operations,
  • and actions when work has progress, cancellation, or a longer lifetime.
  • Define custom interfaces only when existing message packages do not express
  • the domain cleanly.
  • Keep build-time dependencies explicit and source the workspace overlay after
  • a successful build.

3. Practical checkpoint
