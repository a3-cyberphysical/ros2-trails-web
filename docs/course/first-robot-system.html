Your first ROS 2 system

Goal

Launch a complete visible ROS 2 application, discover its graph, change its behavior, and record evidence. You do not need to understand every ROS abstraction before beginning; the inspection steps give those abstractions a concrete purpose.

Time: about 60 minutes. Produces: lesson-01-evidence.md and a small bag.

Do it

Prepare terminals

Use Ubuntu 24.04 with ROS 2 Jazzy Desktop. Open three Bash terminals. Terminal A runs the simulator, Terminal B sends commands, and Terminal C inspects the graph without stopping the running system. In every new terminal:

source /opt/ros/jazzy/setup.bash
printenv ROS_DISTRO
command -v ros2

Expect jazzy and a path to ros2. If either differs, use the local environment contract before continuing.

Run the whole system

In Terminal A, start turtlesim:

ros2 run turtlesim turtlesim_node

In Terminal B, start keyboard control:

source /opt/ros/jazzy/setup.bash
ros2 run turtlesim turtle_teleop_key

Focus Terminal B and move the turtle. This visible behavior is the whole game in miniature: one node owns simulated state, another publishes intent, and typed ROS interfaces connect them.

Inspect before explaining

Keep both processes running. In Terminal C:

source /opt/ros/jazzy/setup.bash
ros2 node list
ros2 topic list -t
ros2 node info /turtlesim
ros2 topic info /turtle1/cmd_vel --verbose
ros2 topic echo /turtle1/pose --once

Draw two boxes for the nodes and arrows for the command and pose topics. Label publisher, subscriber, and message type from command output—not memory.

Expected observations:

  • ros2 node list includes /turtlesim and /teleop_turtle;
  • ros2 topic list -t includes /turtle1/cmd_vel [geometry_msgs/msg/Twist] and /turtle1/pose [turtlesim/msg/Pose];
  • ros2 node info /turtlesim shows the simulator subscribes to command velocity and publishes pose.

Intervene with the graph

Predict the direction first, then publish one bounded command:

ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 1.0}, angular: {z: 0.8}}"

Expect the turtle to make one short curved motion. If nothing visible happens, keep turtlesim running, check that the topic name is /turtle1/cmd_vel, confirm the message type is geometry_msgs/msg/Twist, and look for the one-shot publisher message in the terminal output.

Call a service and inspect a parameter:

ros2 service call /clear std_srvs/srv/Empty '{}'
ros2 param get /turtlesim background_b
ros2 param set /turtlesim background_b 40
ros2 service call /clear std_srvs/srv/Empty '{}'

Expect /clear to erase the turtle trail, ros2 param get to print the current blue background value, and the final /clear to redraw the window with a visibly changed background color after background_b is set to 40.

Explain why continuous velocity is a topic, clearing is a service, and background color is a parameter.

Record evidence

Create a fresh evidence directory. If lesson-01 already exists, choose a new name rather than overwriting it.

mkdir -p ~/ros2_trails_evidence
cd ~/ros2_trails_evidence
ros2 bag record -o lesson-01 /turtle1/cmd_vel /turtle1/pose

Move for ten seconds, then stop the recorder with Ctrl+C. Inspect it:

ros2 bag info ~/ros2_trails_evidence/lesson-01

If you chose a different bag directory name, substitute that name in the ros2 bag info command and in your evidence notes.

Expect a duration close to your recording time and non-zero message counts for both /turtle1/cmd_vel and /turtle1/pose. If the command topic count is zero, repeat the recording while actively moving the turtle from Terminal B.

Verify

Create ~/ros2_trails_evidence/lesson-01-evidence.md containing:

  • ## Graph sketch — your two-node/two-topic drawing;
  • ## Command result — one command and its observed behavior;
  • ## Interface explanation — why the lesson used a topic, service, and parameter;
  • ## Bag evidence — bag duration and message counts;
  • ## Carry forward — one surprise and one question for tf2/RViz.

You are done when you can recreate the graph from clean terminals, predict the manual command, and support your explanation with CLI output. Reading without running the system does not complete the lesson.

Troubleshooting

  • ros2 is not found: source /opt/ros/jazzy/setup.bash in that terminal and check printenv ROS_DISTRO.
  • turtlesim_node is not found: install the local tutorial package with sudo apt update && sudo apt install ros-jazzy-turtlesim, then open a fresh sourced terminal.
  • Teleop does nothing: click the teleop terminal so it owns keyboard focus.
  • ros2 topic echo /turtle1/pose --once hangs: move the turtle once or confirm /turtlesim is still running.
  • ros2 bag record says the output exists: choose a new bag directory name rather than overwriting evidence.

Challenge

Change exactly one linear or angular value, predict the new path, run it, and record whether the result matched. Restore the background parameter if desired.

Use the onsite Help and diagnostic packet if you get stuck. Capture environment, exact command, full error, expected behavior, node/topic lists, and the smallest reproduction before asking for help. Stop all lesson terminals with Ctrl+C when finished.
